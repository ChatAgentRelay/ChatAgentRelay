Documentation Overview

Chat Agent Relay is a standard relay layer between chat platforms and agents. These docs explain the relay path, the adapter boundaries, and how to run and extend the current repository.

What CAR is

CAR sits between chat platforms and agents. It canonicalizes inbound chat traffic into a stable internal event model, applies governance on the message path, makes route decisions, invokes agents through the agent-side boundary, and delivers the response back to the chat platform.

The canonical happy path is:

message.received
  → policy.decision.made
  → route.decision.made
  → agent.invocation.requested
  → agent.response.completed
  → message.send.requested
  → message.sent

When a path is denied, blocked, or fails terminally, CAR records event.blocked rather than silently dropping the outcome.

Channel-side boundary

On the channel side, CAR uses channel adapters to receive provider-native traffic, verify it where applicable, canonicalize it into CAR events, and translate canonical outbound intent back into provider-native delivery behavior.

Slack
Socket Mode ingress, canonicalization, delivery, and progressive update support.
Discord
Gateway ingress, canonicalization, delivery, and slash command support.
WebChat
HTTP-based testing and browser-facing chat integration.

See the channel docs for current built-in integrations and channel-specific setup details.

Agent-side boundary

On the agent side, CAR uses A2A as the standard protocol boundary. The agent adapter accepts canonical invocation context from CAR, maps that request into A2A, and maps the result back into canonical CAR semantics.

A2A
Standard agent-side protocol boundary used by CAR.

CAR is not an agent runtime. Remote agents keep ownership of their internal execution model, private memory, tools, and framework-specific runtime state.

Quick start

Clone the repository and install dependencies with Bun:

git clone https://github.com/ChatAgentRelay/ChatAgentRelay.git
cd ChatAgentRelay
bun install

Add a channel, add an agent, set a route, and start the relay:

cd packages/server
export CAR_ENCRYPTION_KEY="$(openssl rand -hex 32)"
car channel add web --type=webchat
car agent add my-bot --endpoint=http://localhost:8080
car route add --default --agent=my-bot
car start

The built-in default configuration store is SQLite-backed. Set CAR_API_KEY in production to secure the management API.
