Getting Started

Practical setup · copy-paste commands · Bun + TypeScript

Chat Agent Relay sits between your chat platform and your AI agent. This guide gets you from zero to a running server: install dependencies, register channels and agents with the car CLI (pluggable config store with SQLite default + encrypted secrets), start the process, verify with tests or Docker, and hit the HTTP API.

Prerequisites

Before you start, you need:

  • Bun — runtime and package manager for this project.
  • A Slack app with a bot token and app-level token (Socket Mode), or another supported channel.
  • CAR_ENCRYPTION_KEY recommended so tokens and API keys are stored encrypted (AES-256-GCM) in the SQLite config database.

Clone the repo if you have not already:

terminal
$ git clone https://github.com/ChatAgentRelay/ChatAgentRelay.git $ cd ChatAgentRelay

Installation

Install all workspace dependencies from the repository root:

terminal
$ bun install

That pulls everything the monorepo needs so you can run the server and the full test suite.

Configuration

Runtime settings are stored via the ConfigStore interface (default: SqliteConfigStore at ./car.db, override with CAR_DB_PATH; swappable for PostgreSQL or other backends). Set CAR_ENCRYPTION_KEY so sensitive fields are written with AES-256-GCM. Use the car CLI from packages/server:

  • car channel add|list|remove — Slack, Discord, WebChat, …
  • car agent add|list|remove — A2A, LangGraph, HTTP, ACP, …
  • car route add|list|remove — default and pattern routes for multi-agent setups
  • car config set|get — key/value settings

The same data can be managed via /api/channels, /api/agents, /api/routes, and /api/config for automation.

terminal
export CAR_ENCRYPTION_KEY=$(openssl rand -hex 32) car channel add my-slack --type=slack --bot-token=xoxb-... --app-token=xapp-... car agent add my-bot --type=a2a --endpoint=http://... car route add --default --agent=my-bot

Running the server

Start Chat Agent Relay from the server package so Bun resolves the right entrypoint:

terminal
$ cd packages/server && car start

When it is up, the HTTP API is available on the configured port (typically localhost:3000). Use /api/health to confirm the process is live.

Testing

Run the full test corpus from the repository root to validate contracts and behavior across packages:

terminal
$ bun test --recursive # ~542 tests across 43 files (run from repo root).

Use this after dependency upgrades or local changes to ensure nothing regressed at the boundaries.

Docker

To run with containers instead of a local Bun process:

terminal
$ docker compose up -d

Mount the SQLite file (or set CAR_DB_PATH) and provide CAR_ENCRYPTION_KEY so the container can read the same encrypted config.

CLI: car

The car binary manages configuration and runs the server:

  • car channel|agent|route|config — add, list, remove resources in the SQLite config DB.
  • car start — run the relay (same entry as a bare car invocation where supported).
  • car --help — usage.
  • car --version — package version.
  • car --check-config — open the config database and print a summary.
terminal
$ car --check-config $ car --version

HTTP API

With the server listening (default http://localhost:3000), you can:

  • Health — GET /api/health for a quick liveness check.
  • Conversation events — GET /api/conversations/:id/events to inspect the event stream for a conversation.
  • Audit — GET /api/conversations/:id/audit for audit-oriented views of the same conversation.

Replace :id with your conversation identifier from Slack or your channel adapter.

terminal
$ curl -s http://localhost:3000/api/health $ curl -s http://localhost:3000/api/conversations/C123456/events $ curl -s http://localhost:3000/api/conversations/C123456/audit

Connect your agent

If your agent has an HTTP endpoint, you can connect it without writing any adapter code. The built-in GenericHttpBackend supports:

  • Custom headers — Authorization, API keys, or any custom header your agent expects.
  • Custom request body — a builder function that transforms the user message into whatever JSON shape your agent accepts.
  • Response field extraction — a dot-path (e.g. "result.text", "answer") to extract the reply from your agent’s JSON response.

For non-HTTP protocols or more advanced integration patterns:

  • New chat surface — add a channel adapter for platforms beyond the built-in Slack, Discord, and WebChat (e.g. Teams, Telegram, or a custom web client); Chat Agent Relay keeps one internal shape.
  • New agent backend — implement the AgentAdapter interface for any agent runtime while policy, routing, ledger, and delivery stay consistent. Built-in support for A2A, LangGraph, ACP, OpenAI, and generic HTTP.
