Agents

Agents are external AI runtimes that Chat Agent Relay connects to through the AgentAdapter interface. CAR handles ingress, governance, routing, and delivery — the agent just processes the prompt and returns a response.

How it works

When a message arrives from a chat channel, the pipeline evaluates policy rules, selects an agent via route rules, and invokes it through the appropriate adapter. The adapter translates between CAR’s canonical event model and the agent’s native protocol.

Every adapter implements the same AgentAdapter interface, which means the pipeline, ledger, and delivery layer work identically regardless of which agent backend you choose. Swap agents without changing anything else.

Available adapters

Pick the adapter that matches your agent’s protocol:

🌐
A2A Protocol
Google’s Agent-to-Agent standard. Best for: agents already exposing A2A endpoints.
🧩
LangGraph
LangGraph Platform API. Best for: LangGraph / LangChain users.
🔗
HTTP
Any HTTP endpoint. Best for: custom agents, workflow platforms (n8n, Dify), prototyping.
💻
ACP
Agent Client Protocol. Best for: coding agents (Claude Code, Gemini CLI).

The AgentAdapter interface

All native adapters implement AgentAdapter, which is aligned with the A2A protocol’s message semantics. The interface supports:

  • invoke — send a message and receive a complete response.
  • invokeStreaming — receive response deltas as they arrive (SSE / streaming).
  • HITL signals — agent.input.requested and agent.input.provided events for human-in-the-loop workflows.

Legacy BackendAdapter implementations (HTTP, OpenAI) are wrapped via legacyBridge() so they work seamlessly in the same pipeline.

Registering an agent

Use the car CLI to register agents. Each agent gets a unique name and type:

car agent add my-agent --type=a2a --endpoint=http://localhost:9000
car agent add my-lg    --type=langgraph --endpoint=http://localhost:8123
car agent add my-http  --type=http --endpoint=http://localhost:5000/chat
car agent add claude   --type=acp --command=claude

Then create a route rule so the pipeline knows which agent handles which messages:

car route add --default --agent=my-agent
