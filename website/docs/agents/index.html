Agents

Agents are external AI runtimes that Chat Agent Relay connects to through the AgentAdapter interface via the A2A (Agent-to-Agent) protocol — the universal standard for agent interoperability. CAR handles ingress, governance, routing, and delivery; the agent just processes the prompt and returns a response.

How it works

When a message arrives from a chat channel, the pipeline evaluates policy rules, selects an agent via route rules, and invokes it through the appropriate adapter. The adapter translates between CAR’s canonical event model and the agent’s native protocol.

CAR uses a single protocol — A2A — to talk to all agents. Every agent implements the same AgentAdapter interface, which means the pipeline, ledger, and delivery layer work identically regardless of which agent you connect. Swap agents without changing anything else.

The A2A adapter

CAR connects to agents via the A2A (Agent-to-Agent) protocol — an open standard by Google adopted by 150+ organizations. Any agent runtime that speaks A2A works out of the box.

HTTP-based agent protocol. Works with CrewAI, Google ADK, AutoGen, Mastra, LangGraph, and any A2A-compliant runtime.

Framework and tool integration paths

Most teams arrive here with a framework, SDK, or coding tool rather than a raw A2A URL. The practical rule is simple: if the runtime exposes an A2A server directly, or can sit behind a small A2A bridge, CAR can route to it through the same car agent add --endpoint=... flow.

LangGraph and LangChain path

LangGraph is the most direct route for teams in the LangChain ecosystem. If you deploy a graph behind an A2A-compatible endpoint, CAR connects to it directly. For LangChain applications, the common path is to wrap or host the LangChain runtime behind a LangGraph-style or python-a2a-compatible A2A server, then give CAR that resulting endpoint. In other words: LangChain itself is usually not what CAR talks to; CAR talks to the A2A server you place in front of the LangChain app.

Recommended path If you already use LangGraph, publish that graph as your A2A boundary and connect CAR directly. If you use plain LangChain, add a thin A2A wrapper in front of the chain or agent runtime rather than trying to make CAR talk to LangChain-specific internals.

Coding tools and local agent runtimes

The recommended pattern for coding tools is to keep the tool-specific protocol private and place a stable A2A façade in front of it. That façade can be a dedicated bridge, an MCP-to-A2A relay, or a general-purpose gateway that exposes one HTTP endpoint for CAR.

The AgentAdapter interface

All adapters implement AgentAdapter, which is aligned with A2A protocol semantics:

  • invoke() — send a message and receive a complete response.
  • stream() — async generator yielding text_delta, status, input_required, and artifact events as they arrive.
  • resume() — continue a session after HITL or follow-up input.
  • resumeStream() — streaming variant of resume; yields deltas while continuing a session.
  • cancel() — abort an in-progress invocation.
  • describeCapabilities() — declare what the adapter supports (streaming, HITL, cancel, artifacts).

All methods except invoke() and describeCapabilities() are optional. The pipeline uses describeCapabilities() to determine which features to activate.

Registering an agent

Use the car CLI to register agents. Each agent gets a unique name and an A2A endpoint:

car agent add my-agent --endpoint=http://localhost:9000

Then create a route rule so the pipeline knows which agent handles which messages:

car route add --default --agent=my-agent
