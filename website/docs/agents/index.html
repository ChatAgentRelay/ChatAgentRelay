Agents

Chat Agent Relay is a standard relay layer between chat platforms and agents. On the agent side, CAR uses A2A as the standard protocol boundary so the relay path stays consistent while remote agent runtimes keep ownership of their internal execution model, tools, and private state.

Agent-side boundary

CAR does not run the agent internally. The agent-side boundary exists so CAR can hand off a routed turn, receive the result in canonical form, and continue the governed message path through delivery, replay, and audit.

That keeps responsibilities clear:

  • CAR owns canonical events, governance, routing, delivery orchestration, and append-only audit truth.
  • The remote agent runtime owns prompt execution, tool use, private memory, framework-specific state, and internal orchestration.

Where A2A fits

A2A is the standard protocol boundary CAR uses on the agent side. It is not the primary product identity of CAR; it is how the relay talks to remote agents once routing has selected the destination. 

message.received
→ policy.decision.made
→ route.decision.made
→ agent.invocation.requested
→ A2A invocation
→ agent.response.completed
→ message.send.requested
→ message.sent

This is what lets the rest of the relay path stay stable across different agent implementations.

What CAR expects from the agent side

At the boundary, CAR needs a small set of predictable behaviors.

ConcernWhat CAR needs
InvocationA routable remote agent endpoint that can accept a turn and return a result
CapabilitiesA declared feature surface such as streaming, resumable interaction, HITL, cancellation, or artifacts where supported
Session continuityA stable session handle when the remote runtime supports multi-turn or resumable flows
Structured failureErrors that can be represented on the canonical path instead of becoming silent drops

Current supported agent path

In the current repository, the built-in agent-side adapter is the A2A adapter. That reflects CAR's present architectural baseline: a relay-centered system with one standard agent-side protocol boundary.

Extension capabilities

Some agent-side behaviors are extensions layered onto the same relay path rather than part of the minimum boundary.

  • Streaming — partial output can be surfaced progressively while still ending in a final canonical completion event.
  • Resumable interaction / HITL — CAR can pause and resume the path when the agent requests additional human input.
  • Cancellation — CAR can request that an in-progress invocation stop when the remote runtime supports it.
  • Artifacts — the agent side can return structured outputs that remain associated with the canonical path.

Registering an agent

Use the car CLI to register a remote agent endpoint and route traffic to it.

car agent add my-agent --endpoint=http://localhost:9000
car route add --default --agent=my-agent
Boundary discipline CAR is not an agent runtime or general-purpose orchestration framework. The agent-side boundary is intentionally narrow so provider-native chat behavior stays at the channel edge and runtime-private execution behavior stays behind the agent edge.
