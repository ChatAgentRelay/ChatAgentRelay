A2A

A2A is the standard protocol boundary between Chat Agent Relay and remote agents. CAR uses it to invoke agents, surface extension capabilities such as streaming or resumable interaction where supported, and map outcomes back onto the canonical relay path.

What A2A means in CAR

CAR is a standard relay layer between chat platforms and agents. On the agent side, A2A is the protocol boundary CAR speaks once routing has selected the destination agent.

This keeps the relay path stable while allowing remote runtimes to keep ownership of their own execution internals.

  • CAR owns canonical events, governance, routing, delivery orchestration, replay, and auditability.
  • The remote agent runtime owns prompts, tools, memory, framework-specific state, and internal orchestration.

Where A2A appears on the message path

message.received
  → policy.decision.made
  → route.decision.made
  → agent.invocation.requested
  → A2A invocation
  → agent.response.completed
  → message.send.requested
  → message.sent

If invocation fails terminally or the path is blocked, CAR records event.blocked so the outcome remains replayable and explainable.

Current implementation

In the current repository, the built-in agent-side adapter lives in backend-a2a. That package is an implementation detail of the current codebase; the architectural point is that CAR uses A2A as the standard agent-side boundary.

Register an A2A agent

Use the car CLI to add a remote A2A endpoint, then route traffic to it.

car agent add my-a2a --type=a2a --endpoint=http://localhost:9000
car route add --default --agent=my-a2a

Extension capabilities over A2A

The minimum boundary is request/response invocation. Additional behaviors are extensions layered onto the same boundary when the remote agent supports them.

CapabilityMeaning in CAR
StreamingPartial output can be surfaced progressively before the final canonical completion event
HITL / resumable interactionThe agent can request human input and later continue the same interaction
CancellationCAR can request that an in-progress invocation stop
ArtifactsThe agent can return structured outputs associated with the canonical path

Capability discovery

The adapter can inspect agent metadata exposed by the remote endpoint and use that information to describe supported capabilities. If the endpoint does not expose enough capability detail, CAR still treats the remote service as an A2A boundary, but extension behavior depends on what the implementation can actually support.

Streaming and human input

Streaming and HITL do not redefine the relay architecture. They are extension behaviors carried through the same governed message path. When supported, CAR can surface partial output, emit canonical human-input request events, and resume the same interaction later.

Boundary discipline CAR does not use A2A to become a general-purpose runtime abstraction layer. It uses A2A as a stable protocol boundary so the relay path remains consistent while runtime-private behavior stays behind the agent edge.
