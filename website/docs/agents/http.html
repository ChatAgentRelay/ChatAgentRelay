HTTP Agent

Connect any HTTP endpoint as an agent backend. Custom headers, request body builders, and response field extraction give you maximum flexibility.

Most flexible adapter This is the most flexible adapter — it can connect to any HTTP-speaking service including n8n, Dify, Flowise, or custom APIs.

Overview

The HTTP adapter sends a POST request to your endpoint with the user’s message and extracts the agent’s reply from the JSON response. It works with any service that accepts HTTP requests and returns JSON — no protocol compliance required.

This is a legacy BackendAdapter implementation. The pipeline wraps it via legacyBridge() so it integrates seamlessly with the AgentAdapter-based pipeline. You get the same ledger, governance, and delivery guarantees as native adapters.

Register an HTTP agent

Use the car CLI to add an HTTP agent:

car agent add my-http --type=http --endpoint=http://localhost:5000/chat

Then route messages to it:

car route add --default --agent=my-http

Configuration options

Option Required Default Description
endpoint Yes — Full URL of the HTTP endpoint (e.g. http://localhost:5000/chat).
responseTextField No "text" Dot-path to extract the reply from the JSON response (e.g. "result.text", "answer").
timeoutMs No 30000 Request timeout in milliseconds.
headers No {} Custom HTTP headers (e.g. Authorization, API keys). Stored encrypted when CAR_ENCRYPTION_KEY is set.

Request format

By default, the adapter sends a JSON body with the user’s message and conversation context:

{
  "message": "What is the weather today?",
  "conversation_id": "C123456",
  "user_id": "U789",
  "channel": "slack"
}

Your endpoint should return a JSON object. The adapter extracts the reply using the responseTextField dot-path:

// If responseTextField = "result.text"
{
  "result": {
    "text": "It's sunny and 72°F today."
  }
}

// If responseTextField = "answer" (default: "text")
{
  "answer": "It's sunny and 72°F today."
}

Custom headers

Pass authentication tokens, API keys, or any custom headers your service expects:

car agent add my-api --type=http \
  --endpoint=https://api.example.com/v1/chat

car config set agent.my-api.headers.Authorization "Bearer sk-..."
car config set agent.my-api.headers.X-Custom-Header "my-value"

Common use cases

  • n8n / Dify / Flowise — point the endpoint at your workflow’s webhook URL.
  • Custom microservices — any REST API that accepts a message and returns a response.
  • Prototyping — stand up a quick endpoint and iterate without committing to a protocol.
  • Legacy systems — wrap existing APIs behind CAR’s governance and delivery pipeline.

Full example

# Register an n8n webhook as an agent
car agent add n8n-workflow --type=http \
  --endpoint=https://n8n.internal/webhook/chat \
  --response-text-field=output.reply

# Add an API key header
car config set agent.n8n-workflow.headers.X-Api-Key "abc123"

# Route messages mentioning "workflow" to this agent
car route add --pattern="text:*workflow*" --agent=n8n-workflow

# Start the relay
car start
