LangGraph Agent

Integrate agents built on LangGraph Platform with Chat Agent Relay. Thread-based sessions, streaming responses, and interrupt/resume for human-in-the-loop workflows.

Overview

LangGraph is LangChain’s framework for building stateful, multi-step agent workflows. The LangGraph Platform exposes these agents via a REST API with built-in thread management, checkpointing, and interrupt semantics.

CAR’s backend-langgraph package is a native AgentAdapter that communicates directly with the LangGraph Platform API. It maps CAR conversations to LangGraph threads, handles streaming deltas, and translates interrupts into agent.input.requested / agent.input.provided events.

Register a LangGraph agent

Use the car CLI to register:

car agent add my-lg --type=langgraph \
  --endpoint=http://localhost:8123 \
  --assistant-id=my-assistant

Then route messages to it:

car route add --default --agent=my-lg

Configuration options

Option Required Default Description
endpoint Yes — LangGraph Platform API URL (e.g. http://localhost:8123).
assistantId No "default" The assistant (graph) to invoke on the platform.
apiKey No — API key for LangGraph Cloud deployments. Stored encrypted when CAR_ENCRYPTION_KEY is set.
timeoutMs No 30000 Request timeout in milliseconds.
headers No {} Additional HTTP headers sent with every request.

Thread-based sessions

LangGraph uses threads to maintain conversational state. CAR automatically maps each conversation_id to a LangGraph thread. On the first message in a conversation, the adapter creates a new thread; subsequent messages in the same conversation reuse the existing thread, preserving multi-turn context.

Streaming

When invoking a LangGraph agent, the adapter uses the streaming endpoint by default. Response tokens arrive as server-sent events and are forwarded through the pipeline in real time. Channels that support message editing (Slack, Discord) progressively update the reply as deltas arrive.

Interrupts (HITL)

LangGraph graphs can include interrupt nodes that pause execution and wait for human input. When the adapter detects an interrupt:

  1. CAR emits an agent.input.requested event with the interrupt payload.
  2. The channel adapter presents the prompt to the user.
  3. The user’s response is captured as agent.input.provided.
  4. The adapter resumes the LangGraph thread with the provided input.

This enables approval gates, clarification loops, and multi-step confirmation workflows.

Full example

# Register a LangGraph Cloud agent
car agent add support-bot --type=langgraph \
  --endpoint=https://my-deployment.langgraph.cloud \
  --assistant-id=support-agent \
  --api-key=lsv2_pt_...

# Route customer-support channels to it
car route add --pattern="channel:support-*" --agent=support-bot

# Start the relay
car start
