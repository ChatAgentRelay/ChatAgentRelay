ACP Agent

Connect coding agents via the Agent Client Protocol. CAR spawns the agent as a subprocess and communicates over JSON-RPC via stdin/stdout.

What is ACP?

The Agent Client Protocol (ACP) is a local communication protocol designed for coding agents like Claude Code and Gemini CLI. Instead of HTTP, ACP agents run as child processes and exchange JSON-RPC messages over standard I/O streams.

CAR’s backend-acp adapter spawns the agent process, sends user messages via stdin, and reads responses from stdout. This makes it possible to trigger coding tasks from a chat message — a Slack mention can kick off a code review, refactor, or implementation task.

Register an ACP agent

Use the car CLI to register a coding agent:

car agent add claude --type=acp --command=claude --permission-policy=auto-approve

Then route messages to it:

car route add --default --agent=claude

Configuration options

Option Required Default Description
command Yes — The executable to spawn (e.g. claude, gemini).
args No [] Arguments passed to the command (e.g. ["--model", "opus"]).
workDir No "." Working directory for the spawned process. Controls which codebase the agent operates on.
timeoutMs No 300000 Maximum time to wait for a response (default 5 minutes; coding tasks can be long-running).
permissionPolicy No "prompt" How the agent handles tool-use permissions: "auto-approve", "prompt", or "deny".

How it works

  1. Spawn — when the pipeline invokes the ACP adapter, it spawns the agent as a child process using the configured command and args.
  2. Send — the user’s message is written to the process’s stdin as a JSON-RPC request.
  3. Receive — the adapter reads the JSON-RPC response from stdout.
  4. Complete — the response text is mapped into a canonical agent.response.completed event and handed to the delivery layer.

Permission policy

Coding agents often need to read/write files, run commands, or access the network. The permissionPolicy option controls how these requests are handled:

  • auto-approve — all tool-use requests are approved automatically. Best for trusted environments.
  • prompt — the agent pauses and waits for explicit approval (requires HITL-capable channel).
  • deny — all tool-use requests are denied. The agent can only generate text responses.

Use cases

  • Code review — mention your bot in Slack with a PR link, and the agent reviews the diff.
  • Automated refactoring — ask the agent to rename a function across the codebase from a chat message.
  • Implementation tasks — describe a feature in Discord and let the coding agent build it.
  • Debugging — paste an error message and have the agent investigate and suggest fixes.

Full example

# Register Claude Code as an agent
car agent add claude-code --type=acp \
  --command=claude \
  --work-dir=/home/dev/my-project \
  --permission-policy=auto-approve

# Register Gemini CLI as a second agent
car agent add gemini --type=acp \
  --command=gemini \
  --work-dir=/home/dev/my-project

# Route coding requests to Claude, everything else to Gemini
car route add --pattern="text:*code*" --agent=claude-code
car route add --default --agent=gemini

# Start the relay
car start
