DingTalk / 钉钉

Connect DingTalk (钉钉) robots to your AI agents. Supports robot webhook callbacks, session-based reply, group and private chat handling, and staff identity mapping.

Prerequisites

Set up a DingTalk custom robot:

  1. Create a robot — in a DingTalk group, go to Group Settings → Smart Group Assistant → Add Robot → Custom Robot.
  2. Configure security — choose IP allowlist, custom keyword, or HMAC-SHA256 signature verification.
  3. Set the message callback URL — point it to your CAR server endpoint that handles DingTalk webhooks.
  4. Copy the webhook URL — for outgoing messages.
Enterprise App Robot For organization-wide deployment, create an Enterprise Internal App robot in the DingTalk Developer Console. This supports the full OpenAPI, richer message types, and more fine-grained permission control.

Add to CAR

car channel add my-dingtalk \
  --type=dingtalk \
  --webhook-url=https://oapi.dingtalk.com/robot/send?access_token=xxx

Features

Session webhook reply

Each incoming message includes a temporary sessionWebhook URL that allows direct reply to the conversation. CAR uses this by default for delivering responses, ensuring replies go to the correct group/DM context. The session webhook has an expiration time (typically 1 hour), which is tracked in provider_extensions.

Group and private chat

The adapter supports both 1-on-1 conversations (conversationType: "1") and group chats (conversationType: "2"). The conversationType is preserved in provider_extensions.

Staff identity

When available, the sender’s senderStaffId and senderCorpId are preserved, enabling integration with enterprise identity systems.

Limitations

  • No streaming — DingTalk’s webhook API does not support message editing or progressive updates. Responses are delivered as a single message.
  • Rate limiting — each robot can send a maximum of 20 messages per minute. Exceeding this triggers a 10-minute cooldown.
  • Text only — only msgtype: "text" is currently supported for ingestion. Rich message types (Markdown, ActionCard) can be sent but not received.

Provider extensions

FieldTypeDescription
msg_idstringDingTalk message ID
conversation_typestring1 (private) or 2 (group)
conversation_titlestringGroup name (when in a group)
sender_staff_idstringEnterprise staff ID (when available)
is_adminbooleanWhether the sender is a group admin
session_webhookstringTemporary reply webhook URL
chatbot_user_idstringRobot user ID in DingTalk

Idempotency

The idempotency key is dt-{msgId}, preventing duplicate processing of the same message callback.
