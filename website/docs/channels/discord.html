Discord

Discord is a channel adapter in Chat Agent Relay. It handles Discord-specific ingress and delivery behavior at the chat-platform boundary, including Gateway connectivity, threaded conversations, reactions, slash commands, embeds, and message updates for streaming-capable paths.

Discord boundary

The Discord adapter receives provider-native Discord events, interprets them according to Discord's platform rules, canonicalizes them into CAR events, and translates outbound canonical intent back into Discord-native send or update behavior.

Once the event has crossed that boundary, CAR continues on the same governed message path used for every other channel.

Prerequisites

Create a Discord bot at the Discord Developer Portal:

  1. Create an application and add a bot under the Bot tab.
  2. Enable the message content intent if your deployment needs to read guild-channel message text.
  3. Copy the bot token and keep it private.
  4. Invite the bot with the permissions needed for your deployment, such as sending messages, reading history, using slash commands, adding reactions, and embedding links where applicable.

Registering Discord

Register the Discord channel with the car CLI:

car channel add my-discord \
  --type=discord \
  --bot-token=your-discord-bot-token
Encrypted secrets When CAR_ENCRYPTION_KEY is set, the Discord bot token is stored encrypted in the config database.

Discord-specific behavior

ConcernDiscord behavior at the boundary
Ingress transportThe adapter receives events through the Discord Gateway and uses Discord's REST APIs for outbound delivery
Conversation shapeGuild channels, direct messages, and thread channels influence how conversation continuity is mapped into the canonical path
Streaming presentationWhen the agent side supports streaming, Discord messages can be progressively updated as output arrives
CommandsDiscord slash commands can be canonicalized as command events on the same relay path
Rich message renderingDiscord-native embeds can present structured outbound content at the provider boundary
Edits and reactionsDiscord-specific edits, deletions, and reactions can be preserved as canonical extension events where supported

Access behavior

The Discord adapter supports provider-specific access controls that remain at the channel boundary.

  • Guild allowlist — restrict the adapter to specific Discord servers.
  • Channel permissions — rely on Discord's native permission model to control where the bot can read or send messages.
  • Thread participation — the bot can participate in existing threads or other Discord conversation surfaces the platform permits.

Configuration options

Option CLI flag Required Description
botToken --bot-token Yes Discord bot token used for Gateway authentication and outbound delivery
guildAllowlist --guild-allowlist No Restrict the adapter to specific guild IDs
Boundary discipline The Discord adapter is responsible for Discord-specific transport and delivery behavior. Governance, routing, A2A invocation, replay, and auditability remain CAR core responsibilities on the canonical message path.
