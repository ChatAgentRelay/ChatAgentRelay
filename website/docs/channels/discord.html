Discord

Connect Discord servers to your AI agents using the Gateway WebSocket connection. Supports streaming, embeds, slash commands, and guild-level access control.

Prerequisites

Create a Discord bot at the Discord Developer Portal:

  1. Create an application and add a Bot under the Bot tab.
  2. Enable the MESSAGE_CONTENT intent — under Bot → Privileged Gateway Intents, toggle Message Content Intent. This is required for the bot to read message text in guild channels.
  3. Copy the bot token — under Bot, click “Reset Token” and save it securely.
  4. Invite the bot — under OAuth2 → URL Generator, select the bot scope with these permissions:
    • Send Messages
    • Send Messages in Threads
    • Read Message History
    • Add Reactions
    • Use Slash Commands
    • Embed Links
    Use the generated URL to add the bot to your server.

Add to CAR

Register the Discord channel with the car CLI:

car channel add my-discord \
  --type=discord \
  --bot-token=your-discord-bot-token
Tokens are encrypted at rest When CAR_ENCRYPTION_KEY is set, the bot token is stored with AES-256-GCM encryption in the SQLite config database.

Features

Gateway connection

The Discord adapter connects via the Gateway WebSocket API, maintaining a persistent connection with automatic heartbeat and reconnection. No webhook URL or public endpoint is required.

Streaming

When the connected agent supports streaming, Discord messages are progressively edited with incoming deltas. Users see the response build up in real time.

Threads

Responses in thread channels maintain conversation context via the canonical conversation_id. The bot can participate in existing threads or create new ones.

Reactions

Reaction events from users are canonicalized as reaction.received events and flow through the pipeline like any other event.

Rich messages (Embeds)

Agent responses are rendered as Discord embeds when they contain structured content. Code blocks, formatted text, and multi-field layouts are supported.

Slash commands

Register slash commands in the Discord Developer Portal. CAR canonicalizes them as command.received events and routes them through the standard pipeline. Responses are sent as interaction replies.

Configuration options

Option CLI flag Required Description
botToken --bot-token Yes Discord bot token from the Developer Portal
guildAllowlist --guild-allowlist No Comma-separated guild (server) IDs to restrict the bot to

Access control

The Discord adapter supports guild-level access control:

  • Guild allowlist — restrict the bot to specific Discord servers by providing a list of guild IDs. Messages from other servers are ignored.
  • Channel permissions — use Discord’s built-in role and channel permission system to control where the bot can read and send messages.
Edit and delete events The adapter captures message edits and deletions, canonicalizing them as message.updated and message.deleted events. These flow through the ledger for full audit trail support.
