Slack

Slack is a channel adapter in Chat Agent Relay. It handles Slack-specific ingress and delivery behavior at the chat-platform boundary, including Socket Mode, threaded conversations, reactions, slash commands, and message updates for streaming-capable paths.

Slack boundary

The Slack adapter receives provider-native Slack events, verifies and interprets them according to Slack's platform rules, canonicalizes them into CAR events, and translates outbound canonical intent back into Slack-native send or update behavior.

Inside CAR, the rest of the relay path stays the same regardless of whether the message originated in Slack or another channel.

Prerequisites

Before adding Slack to CAR, create a Slack app at api.slack.com/apps:

  1. Enable Socket Mode — under Settings → Socket Mode, turn it on and create an app-level token with the connections:write scope.
  2. Add bot token scopes — under OAuth & Permissions, add the scopes your deployment needs, such as chat:write, app_mentions:read, message history scopes, reactions:write, and commands where applicable.
  3. Install the app into the target workspace and copy the bot token.
  4. Subscribe to events that match the Slack-side inputs you want CAR to receive.

Registering Slack

Register the Slack channel with the car CLI:

car channel add my-slack \
--type=slack \
--bot-token=xoxb-your-bot-token \
--app-token=xapp-your-app-token
Encrypted secrets When CAR_ENCRYPTION_KEY is set, Slack bot tokens and app tokens are stored encrypted in the config database.

Slack-specific behavior

ConcernSlack behavior at the boundary
Ingress transportSocket Mode delivers Slack events over an app-managed connection rather than a public webhook endpoint
Conversation shapeSlack threads and direct messages shape how conversation continuity is mapped into the canonical path
Streaming presentationWhen the agent side supports streaming, Slack can progressively update a message using Slack-native edit behavior
CommandsSlack slash commands can be canonicalized as command events on the same relay path
Reactions and editsSlack-native reactions, message edits, and related events can be preserved as canonical extension events where supported

Access behavior

The Slack adapter can be configured to fit common workspace interaction patterns.

  • Direct messages — CAR can process direct messages sent to the bot.
  • Channel participation — the bot can operate in channels where it has been added.
  • Mention gating — when enabled, channel messages only enter the relay path if they explicitly mention the bot.
  • Acknowledgment reactions — Slack-native reactions can signal that a turn has been accepted for processing.

Configuration options

Option CLI flag Required Description
botToken --bot-token Yes Slack bot token used for sending and updating messages
appToken --app-token Yes Slack app-level token used for Socket Mode connectivity
mentionOnly --mention-only No Restrict channel-triggered turns to explicit bot mentions
ackEmoji --ack-emoji No Emoji used for acknowledgment reactions when enabled
ackEnabled --ack-enabled No Enable or disable Slack-side acknowledgment reactions
Boundary discipline The Slack adapter is responsible for Slack-specific transport and delivery behavior. Governance, routing, A2A invocation, replay, and auditability remain CAR core responsibilities on the canonical message path.
