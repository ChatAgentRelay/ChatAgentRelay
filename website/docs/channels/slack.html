Slack

Connect Slack workspaces to your AI agents using Socket Mode. Supports streaming responses, threaded conversations, reactions, Block Kit output, and slash commands.

Prerequisites

Before adding Slack to CAR, create a Slack app at api.slack.com/apps:

  1. Enable Socket Mode — under Settings → Socket Mode, toggle it on. This generates an App-Level Token (xapp-...) with the connections:write scope.
  2. Add bot token scopes — under OAuth & Permissions, add these Bot Token Scopes:
    • chat:write — send messages
    • app_mentions:read — respond to @mentions
    • channels:history — read channel messages
    • groups:history — read private channel messages
    • im:history — read DMs
    • reactions:write — add acknowledgment reactions
    • commands — slash commands (if used)
  3. Install the app to your workspace. Copy the Bot User OAuth Token (xoxb-...).
  4. Subscribe to events — under Event Subscriptions, add app_mention, message.channels, message.groups, message.im.

Add to CAR

Register the Slack channel with the car CLI:

car channel add my-slack \
  --type=slack \
  --bot-token=xoxb-your-bot-token \
  --app-token=xapp-your-app-token
Tokens are encrypted at rest When CAR_ENCRYPTION_KEY is set, bot tokens and app tokens are stored with AES-256-GCM encryption in the SQLite config database. Always set this in production.

Features

Streaming

When the connected agent supports streaming (e.g., A2A or LangGraph), Slack progressively updates the response message using chat.update. Users see the reply build up in real time rather than waiting for the full response.

Threads

Responses are posted as threaded replies when the original message is in a thread. Conversation context is maintained per-thread via the canonical conversation_id.

Acknowledgment reactions

CAR adds a configurable emoji reaction (default: eyes) to incoming messages to signal that processing has started. The reaction is removed when the response is delivered.

Rich messages

Agent responses are rendered as Slack Block Kit output. Code blocks, headers, lists, and bold/italic formatting are preserved. Long responses are automatically chunked to stay within Slack’s message length limits.

Slash commands

Register slash commands in your Slack app configuration. CAR canonicalizes them as command.received events and routes them through the standard pipeline.

Mention-only mode

When mentionOnly is enabled, the bot only responds to messages that @mention it. Other messages in the channel are ignored. DMs are always processed.

Configuration options

Option CLI flag Required Description
botToken --bot-token Yes Bot User OAuth Token (xoxb-...)
appToken --app-token Yes App-Level Token for Socket Mode (xapp-...)
mentionOnly --mention-only No Only respond to @mentions in channels (default: false)
ackEmoji --ack-emoji No Emoji name for acknowledgment reaction (default: eyes)
ackEnabled --ack-enabled No Enable/disable acknowledgment reactions (default: true)

Access control

The Slack adapter supports two access modes:

  • DM mode — the bot responds to any direct message.
  • Channel mode — the bot is added to specific channels. Combined with mentionOnly, this limits which messages trigger agent invocations.

For workspace-level restrictions, use Slack’s built-in app management to control which channels the bot can be added to.
