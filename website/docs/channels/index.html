Channels

Channels are chat-platform adapters that normalize incoming messages into canonical events and deliver responses back to the platform. Each channel implements the ChannelAdapter interface, which unifies ingress (canonicalization) and egress (sender creation) in a single boundary. All six channel types below are wired into the server runtime and can be registered with car channel add.

How channels work

When a user sends a message on Slack, Discord, Telegram, Lark, DingTalk, or a web UI, the channel adapter:

  1. Receives the raw platform event (webhook, socket, HTTP POST).
  2. Validates authentication and extracts the message content.
  3. Emits a message.received canonical event with normalized fields.
  4. Delivers the agent’s response back to the platform in its native format.

This means your agent code never deals with platform specifics — it receives and returns the same canonical shape regardless of where the message originated.

Adding a channel

Use the car CLI to register a channel. Each type has its own required options:

car channel add my-slack      --type=slack      --bot-token=xoxb-... --app-token=xapp-...
car channel add my-discord    --type=discord    --bot-token=...
car channel add web           --type=webchat
car channel add my-telegram   --type=telegram   --bot-token=123456:ABC...
car channel add my-lark       --type=lark       --app-id=cli_xxx --app-secret=yyy
car channel add my-dingtalk   --type=dingtalk   --webhook-url=https://oapi.dingtalk.com/robot/send?access_token=xxx

Channels are hot-pluggable — changes take effect without restarting the server where supported. See the individual channel pages for full configuration details.
