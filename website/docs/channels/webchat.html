WebChat

The simplest channel adapter. HTTP-based with no external app setup, persistent connections, or third-party accounts required. Ideal for testing, internal tools, and custom web UIs.

Overview

WebChat is a lightweight HTTP channel that accepts messages via POST requests and returns agent responses synchronously. There’s no WebSocket, no OAuth flow, no external app registration — just send a JSON payload and get a response.

This makes it the fastest way to verify your CAR installation is working, and a natural fit for:

  • Local development — test agents without configuring Slack or Discord.
  • Internal tools — embed chat in admin panels or dashboards.
  • Custom web UIs — build your own chat frontend that talks to any agent through CAR.
  • CI/CD pipelines — automated integration tests against the relay.

Add to CAR

Register the WebChat channel — no tokens needed:

car channel add web --type=webchat

That’s it. The channel is ready to receive messages on the server’s HTTP API.

Usage

Send messages with a POST request to the WebChat endpoint:

curl -X POST http://localhost:3000/api/webchat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Hello, agent!",
    "conversation_id": "test-123",
    "user_id": "user-1"
  }'

The response contains the agent’s reply in the same HTTP response:

{
  "reply": "Hello! How can I help you today?",
  "conversation_id": "test-123"
}
Full pipeline Even though WebChat is simple, every message flows through the complete 7-event pipeline: governance, routing, agent invocation, delivery, and ledger recording. You get the same audit trail and policy enforcement as Slack or Discord.

Configuration options

Option CLI flag Required Description
corsOrigins --cors-origins No Allowed CORS origins for browser-based clients (default: *)

CORS configuration

When embedding WebChat in a browser-based UI, configure CORS to allow requests from your frontend domain:

car channel add web --type=webchat --cors-origins=https://app.example.com

Multiple origins can be comma-separated. The default (*) allows all origins, which is fine for local development but should be restricted in production.

Production CORS Always set explicit CORS origins in production to prevent unauthorized frontends from accessing your relay.

Building a frontend

WebChat is designed to be the backend for your own chat interface. A minimal integration is a single fetch call:

const response = await fetch("http://localhost:3000/api/webchat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    message: userInput,
    conversation_id: sessionId,
    user_id: currentUser
  })
});
const data = await response.json();
displayMessage(data.reply);

Conversation context is maintained server-side via conversation_id, so your frontend only needs to persist the session identifier.
