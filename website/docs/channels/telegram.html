Telegram

Telegram is a channel adapter in Chat Agent Relay. It handles Telegram-specific ingress and delivery behavior at the chat-platform boundary, including Bot API webhooks, bot commands, message editing for streaming-capable paths, and chat-type-specific behavior.

Telegram boundary

The Telegram adapter receives provider-native Bot API updates, interprets them according to Telegram's platform rules, canonicalizes them into CAR events, and translates outbound canonical intent back into Telegram-native send or edit behavior.

Once the update has crossed that boundary, CAR continues on the same governed message path used for every other channel.

Prerequisites

Create a Telegram bot via @BotFather:

  1. Create a new bot and keep the returned bot token private.
  2. Configure the webhook target for the deployment where CAR will receive Telegram updates.
  3. Optionally set bot commands if you want command autocomplete and Telegram-native command discovery.

Registering Telegram

Register the Telegram channel with the car CLI:

car channel add my-telegram \
--type=telegram \
--bot-token=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
Encrypted secrets When CAR_ENCRYPTION_KEY is set, Telegram bot tokens are stored encrypted in the config database.

Telegram-specific behavior

ConcernTelegram behavior at the boundary
Ingress transportThe adapter receives Telegram updates from the Bot API webhook surface
Conversation shapePrivate chats, groups, supergroups, and channels influence how conversation continuity and actor context are mapped into the canonical path
CommandsTelegram bot commands can be canonicalized as command events when the incoming message includes command semantics
Streaming presentationWhen the agent side supports streaming, Telegram can progressively update a message through Telegram-native edit behavior
Provider metadataTelegram-specific fields such as update IDs, chat IDs, and chat types can be preserved in structured provider extensions

Chat behavior

The Telegram adapter supports several Telegram conversation surfaces.

  • Private chats — direct bot conversations.
  • Groups and supergroups — shared chat surfaces with Telegram-specific mention and command behavior.
  • Channel-specific metadata — Telegram-native chat type and message identity can remain available as provider extension data.

Configuration options

Option CLI flag Required Description
botToken --bot-token Yes Telegram Bot API token used for receiving updates and delivering replies

Provider extensions

Telegram-specific metadata can be preserved in provider_extensions.telegram, including fields such as update ID, message ID, chat ID, and chat type.

Idempotency

The adapter can use Telegram update identity to deduplicate repeated webhook deliveries at the provider boundary.

Boundary discipline The Telegram adapter is responsible for Telegram-specific transport and delivery behavior. Governance, routing, A2A invocation, replay, and auditability remain CAR core responsibilities on the canonical message path.
