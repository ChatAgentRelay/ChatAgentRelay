CLI & Config

Configuration in Chat Agent Relay covers the runtime state needed to register channels, agents, routes, and settings for the canonical relay path. The car CLI is the main operational interface for managing that state and starting the server runtime.

What configuration means in CAR

CAR is a relay layer with explicit channel-side boundaries, an agent-side boundary, and a governed canonical message path in the middle. Configuration supplies the runtime state that tells CAR which channel adapters are registered, which agents are available, how routing decisions should be made, and what global settings apply to the running system.

The goal of configuration is not to redefine CAR as a broad control plane. It is to provide the concrete runtime inputs needed for the relay path to operate consistently.

Runtime state CAR stores

CategoryWhat it controls
ChannelsWhich chat-platform boundaries are registered and how each one authenticates or connects
AgentsWhich remote agents are available behind the agent-side boundary
RoutesHow inbound turns are matched to the appropriate agent
SettingsRuntime-wide values such as database path, encryption material, and similar operational parameters

Environment inputs

The default runtime uses a small environment surface.

VariableDefaultDescription
CAR_DB_PATH./car.dbPath to the SQLite database used by the default runtime configuration and storage setup
CAR_ENCRYPTION_KEY(unset)Hex-encoded 256-bit key used to encrypt sensitive configuration fields
Encrypted configuration Sensitive values such as tokens and API keys are encrypted when CAR_ENCRYPTION_KEY is set.

car start

Start the CAR runtime with the currently registered channels, agents, routes, and settings.

car start [--port=3000] [--host=0.0.0.0]

On startup, the runtime loads configuration, initializes registered channel adapters and agent connections, and begins serving the relay path.

car channel

Manage registered channel adapters at the chat-platform boundary.

car channel add <name> --type=<channel-type> [options]
car channel list
car channel show <name>
car channel enable <name>
car channel disable <name>
car channel remove <name>

Use this command group to register and manage Slack, Discord, WebChat, Telegram, Lark, DingTalk, and other channel instances supported by the current runtime.

car agent

Manage registered agents at the agent-side boundary.

car agent add <name> --endpoint=<url> [options]
car agent list
car agent show <name>
car agent enable <name>
car agent disable <name>
car agent remove <name>

In the current repository, agents are registered as remote A2A endpoints behind the standard agent-side boundary.

car route

Manage routing rules that determine which registered agent handles an inbound turn.

car route add --default --agent=<name>
car route add --channel=<channel-name> --agent=<name>
car route add --pattern="regex" --agent=<name>
car route list
car route remove <id>

See the Routing page for rule semantics and evaluation behavior.

car config

Manage key-value settings stored in the runtime configuration layer.

car config set <key> <value>
car config get <key>
car config list

car status

Show a summary of the current registered runtime state.

car status
Boundary discipline The CLI and configuration layer exist to wire the relay runtime together. They do not change the architectural role of CAR: channel boundaries, canonical message path, A2A agent boundary, delivery, replay, and audit remain the core model.
