CLI & Configuration

All runtime configuration lives in a SQLite database managed by the car CLI. Two environment variables, zero config files.

Overview

Chat Agent Relay uses a single SQLite database (configurable via CAR_DB_PATH) as its configuration store. The car CLI provides a complete command-line interface for managing channels, agents, routes, and settings. There are only two environment variables in the entire system:

VariableDefaultDescription
CAR_DB_PATH./car.dbPath to the SQLite configuration database
CAR_ENCRYPTION_KEY(unset)Hex-encoded 256-bit key for AES-256-GCM encryption of sensitive fields (tokens, API keys)
Dual-mode operation When the server is stopped, the CLI writes directly to the SQLite database. When the server is running, the CLI calls the HTTP API instead, enabling hot-reload of channels and agents without restart.
Interactive mode If you omit required parameters, the CLI prompts for them interactively. For example, car channel add my-slack --type=slack will prompt for the bot token and app token.

car start

Start the Chat Agent Relay server. This reads the configuration database, initializes all registered channels and agents, sets up route rules, and begins listening for incoming messages.

car start [--port=3000] [--host=0.0.0.0]

The server exposes the HTTP API on the configured port. Use Ctrl+C or send SIGTERM for graceful shutdown.

car channel

Manage channel adapters. All six types — slack, discord, webchat, telegram, lark, and dingtalk — are wired into the server runtime and registered via this CLI.

car channel add

car channel add <name> --type=<slack|discord|webchat|telegram|lark|dingtalk> [options]

# Examples
car channel add my-slack --type=slack \
  --bot-token=xoxb-... --app-token=xapp-...

car channel add support-discord --type=discord \
  --bot-token=MTIz... --app-id=123456

car channel add web --type=webchat \
  --allowed-origins=https://example.com

Sensitive values like tokens are encrypted at rest when CAR_ENCRYPTION_KEY is set.

car channel list

car channel list

# Output:
# NAME             TYPE      ENABLED
# my-slack         slack     true
# support-discord  discord   true
# web              webchat   true

car channel show

car channel show <name>

Displays full configuration for a channel. Sensitive fields are masked.

car channel enable|disable

car channel enable <name>
car channel disable <name>

Toggle a channel on or off without removing its configuration.

car channel remove

car channel remove <name>

car agent

Manage agent backends. All agents connect via the A2A protocol and are registered via this CLI.

car agent add

car agent add <name> --endpoint=<url> [options]

# Examples
car agent add primary \
  --endpoint=http://localhost:8080/a2a

car agent add support \
  --endpoint=http://agents.internal:9000

car agent list

car agent list

# Output:
# NAME       TYPE        ENABLED
# primary    a2a         true
# support    a2a         true

car agent show

car agent show <name>

car agent enable|disable

car agent enable <name>
car agent disable <name>

car agent remove

car agent remove <name>

car route

Manage routing rules that determine which agent handles each message.

car route add

car route add --default --agent=<name>
car route add --channel=<channel-name> --agent=<name>
car route add --pattern="regex" --agent=<name>

# Examples
car route add --default --agent=primary
car route add --channel=support-discord --agent=coder
car route add --pattern="^/code" --agent=coder

car route list

car route list

# Output:
# ID  TYPE      MATCH              AGENT
# 1   channel   support-discord    coder
# 2   pattern   ^/code             coder
# 3   default   *                  primary

car route remove

car route remove <id>

car config

Manage key-value settings.

car config set

car config set <key> <value>

# Example
car config set log_level debug

car config get

car config get <key>

car config list

car config list

# Output:
# KEY          VALUE
# log_level    debug

car status

Show a summary of the current configuration: registered channels, agents, routes, and whether the server is running.

car status

# Output:
# Server:   running (pid 12345, port 3000)
# Channels: 2 registered (2 enabled)
# Agents:   3 registered (3 enabled)
# Routes:   3 rules
