Storage Backends

Interface-driven storage for configuration and events. SQLite built-in, anything else pluggable.

ConfigStore Interface

The ConfigStore interface defines how Chat Agent Relay persists channels, agents, routes, and key-value settings. Any class implementing this interface can serve as the configuration backend.

MethodDescription
getChannels()List all registered channels
getChannel(name)Get a single channel by name
addChannel(config)Register a new channel
updateChannel(name, config)Update an existing channel
removeChannel(name)Remove a channel
getAgents()List all registered agents
getAgent(name)Get a single agent by name
addAgent(config)Register a new agent
updateAgent(name, config)Update an existing agent
removeAgent(name)Remove an agent
getRoutes()List all routing rules
addRoute(rule)Add a routing rule
removeRoute(id)Remove a routing rule
getConfig(key)Get a config value
setConfig(key, value)Set a config value
listConfig()List all config key-value pairs
deleteConfig(key)Delete a config entry

Default: SqliteConfigStore

The built-in SqliteConfigStore requires zero configuration. It uses SQLite in WAL mode for concurrent read performance and stores the database at the path specified by CAR_DB_PATH (default: ./car.db). 

# Use the default path
car start

# Or specify a custom path
CAR_DB_PATH=/var/lib/car/config.db car start
Encryption at rest Sensitive fields (tokens, API keys) are encrypted with AES-256-GCM when CAR_ENCRYPTION_KEY is set, regardless of storage backend. The encryption happens at the ConfigStore layer, so custom implementations inherit this behavior automatically.

LedgerStore Interface

The LedgerStore interface defines how the append-only event ledger is persisted. Like ConfigStore, it is interface-driven and swappable.

MethodDescription
append(event)Append an event to the ledger
getById(eventId)Retrieve a single event by ID
getByConversationId(id)Get all events for a conversation
getByCorrelationId(id)Get all events sharing a correlation ID

The default implementation uses SQLite (same database or a separate file). An in-memory implementation is also available for testing.

Implementing a Custom Backend

To use PostgreSQL, DynamoDB, or any other storage system, implement the ConfigStore and/or LedgerStore interfaces: 

import type { ConfigStore } from '@chat-agent-relay/config-store';

export class PostgresConfigStore implements ConfigStore {
  constructor(private pool: Pool) {}

  async getChannels() {
    const result = await this.pool.query('SELECT * FROM channels');
    return result.rows;
  }

  async addChannel(config) {
    await this.pool.query(
      'INSERT INTO channels (name, type, config) VALUES ($1, $2, $3)',
      [config.name, config.type, JSON.stringify(config)]
    );
  }

  // ... implement remaining methods
}

Pass your custom store when constructing the pipeline or server: 

import { PostgresConfigStore } from './pg-store';

const configStore = new PostgresConfigStore(pool);
// Pass configStore to server initialization
