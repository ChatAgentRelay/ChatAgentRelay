Multi-Agent Routing

Register multiple agents and define rules that determine which one handles each message.

Overview

Chat Agent Relay supports running multiple agents simultaneously. When a message arrives, the route engine evaluates rules in priority order to decide which agent should handle it. Rules are managed with car route add and stored in the configuration database.

Match Types

There are three match types, evaluated in this priority order:

PriorityTypeMatches OnExample
1 (highest)channelSpecific channel name--channel=support-discord
2patternRegex against message text--pattern="^/code"
3 (lowest)defaultEverything else (catch-all route)--default

The engine checks channel rules first. If none match, it tests pattern rules in order. If nothing matches, the default rule applies. If there is no default rule and nothing matches, the message is blocked with an event.blocked event.

Setting Up Routes

First, register your agents:

car agent add general --endpoint=http://localhost:8080/a2a
car agent add coder --endpoint=http://localhost:8081
car agent add support --endpoint=http://localhost:9000

Then define routing rules:

# Messages from the support channel go to the support agent
car route add --channel=support-discord --agent=support

# Messages starting with /code go to the coding agent
car route add --pattern="^/code" --agent=coder

# Everything else goes to the general agent
car route add --default --agent=general

Evaluation Order

When a message arrives from channel support-discord with text /code fix the bug:

  1. The engine checks channel rules — support-discord matches, routes to support.
  2. Pattern rules are not evaluated because a channel rule already matched.

When a message arrives from channel my-slack with text /code refactor the module:

  1. No channel rule matches my-slack.
  2. Pattern rule ^/code matches, routes to coder.

When a message arrives from my-slack with text hello:

  1. No channel rule matches.
  2. No pattern rule matches.
  3. Default rule applies, routes to general.

Managing Routes

# List all routes
car route list

# Remove a route by ID
car route remove 2

When the server is running, route changes take effect immediately via the HTTP API without restart.

Real-world multi-agent scenario A company uses Slack for internal chat and Discord for customer support. They register three agents: a general-purpose assistant for everyday Slack questions, a specialized coding agent triggered by /code commands, and a customer-facing support agent for the Discord channel. All three share the same ledger and governance layer, but each handles only the traffic routed to it.

Route API

Routes can also be managed via the HTTP API when the server is running:

# List routes
curl -s http://localhost:3000/api/routes

# Add a route
curl -X POST http://localhost:3000/api/routes \
  -H "Content-Type: application/json" \
  -d '{"type":"default","agent":"general"}'

# Remove a route
curl -X DELETE http://localhost:3000/api/routes/2
