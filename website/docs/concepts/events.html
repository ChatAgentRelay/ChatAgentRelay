Event Model

Canonical events are the center of the Chat Agent Relay message path. They make governance, routing, delivery, replay, and audit consistent across channels and agents.

Core message path

The core relay path is a canonical chain of events:

message.received
→ policy.decision.made
→ route.decision.made
→ agent.invocation.requested
→ agent.response.completed
→ message.send.requested
→ message.sent
Event TypeRole in the pathDescription
message.receivedInbound canonicalizationInbound message normalized from the chat platform into CAR's canonical model
policy.decision.madeGovernanceMessage-path governance result before routing
route.decision.madeRoutingSelected route for the turn
agent.invocation.requestedAgent boundaryCanonical invocation handed to the agent-side boundary
agent.response.completedAgent resultAgent result mapped back into canonical form
message.send.requestedOutbound intentCanonical outbound intent prepared for delivery
message.sentDelivery outcomeDelivery success recorded on the canonical path

event.blocked and blocked paths

When a path is denied, blocked, or fails terminally, CAR records event.blocked rather than silently dropping the outcome.

Illustrative examples:

message.received
→ policy.decision.made (deny)
→ event.blocked

message.received
→ policy.decision.made
→ route.decision.made
→ agent.invocation.requested
→ event.blocked

This is what keeps the message path explainable even when processing does not reach a normal completion.

Correlation and causation

All events in one relay path share a correlation_id. Child events also carry a causation_id pointing to the event that directly led to them. 

message.received (causation: null)
→ policy.decision.made (causation: message.received)
→ route.decision.made (causation: policy.decision.made)
→ agent.invocation.requested (causation: route.decision.made)
→ agent.response.completed (causation: agent.invocation.requested)
→ message.send.requested (causation: agent.response.completed)
→ message.sent (causation: message.send.requested)

This makes replay and audit possible without depending on hidden mutable state.

Extension event families

CAR also supports extension event families that enrich the relay path without redefining the core canonical chain.

Messaging extensions

  • message.updated
  • message.deleted
  • reaction.received
  • command.received

Agent extensions

  • agent.status.changed
  • agent.input.requested
  • agent.input.provided

These are useful where supported, but they are not the minimum canonical chain that defines CAR's core relay identity.

Core vs extension The core message path defines the minimum relay chain. Richer interaction signals such as updates, reactions, commands, and resumable input flows are extension semantics layered on top.
