Pipeline

The FirstExecutablePathPipeline is the core orchestrator that ties together policy, routing, agent invocation, and delivery into a single coherent flow.

Overview

The pipeline receives a canonical message.received event and drives it through every stage: governance, routing, agent invocation, and delivery. Each stage emits events to the ledger, building the causal chain. If any stage fails or denies, the pipeline emits event.blocked and stops.

Pipeline Flow

message.received
  │
  ├─▶ canonicalize     Convert platform message to canonical event
  │
  ├─▶ policy           Evaluate governance rules (policyFn)
  │     ├─ allow ──▶ continue
  │     └─ deny  ──▶ event.blocked → stop
  │
  ├─▶ route            Select agent (routeFn → resolveAgent)
  │
  ├─▶ agent            Invoke the selected agent
  │     ├─ success ──▶ agent.response.completed
  │     ├─ stream  ──▶ deltas → agent.response.completed
  │     └─ error   ──▶ event.blocked → stop
  │
  └─▶ delivery         Send response via channel adapter (createSender)
        ├─ success ──▶ message.sent
        └─ exhaust ──▶ event.blocked (DeliveryExhaustedError)

PipelineConfig

The pipeline is configured with a PipelineConfig object that wires together all the components:

PropertyTypeDescription
channelAdapterChannelAdapterThe channel adapter that canonicalizes input and creates senders for delivery
resolveAgent(name: string) => AgentAdapterResolves an agent adapter by name from the registry
routeFn(event) => stringReturns the agent name for a given event (from route rules)
policyFn(event) => PolicyResultEvaluates governance rules; returns allow or deny with reason
ledgerStoreLedgerStoreWhere events are appended
streamingbooleanWhether to use streaming invocation when the agent supports it

Streaming

When streaming is enabled and the agent adapter implements stream(), the pipeline receives incremental deltas as the agent generates its response. Each delta can be forwarded to the chat platform in real time (e.g., updating a Slack message progressively).

The flow for streaming:

  1. Pipeline calls agent.stream(context)
  2. Agent yields text_delta, status, input_required, and artifact events via an async generator
  3. Each event is forwarded to the channel adapter's update mechanism
  4. When the generator returns, the full response is captured in agent.response.completed
  5. Delivery proceeds with the final message
Streaming support The A2A adapter supports streaming natively via SSE using the message/stream JSON-RPC method. If an agent does not support streaming, the pipeline falls back to invoke() automatically.

Error Handling

The pipeline catches errors at every stage and converts them into event.blocked events. This ensures the ledger always records what happened, even on failure:

  • Policy deny — policyFn returns { allow: false, reason: "..." }. An event.blocked is emitted with the deny reason.
  • Agent error — The agent throws, times out, or returns an error. An event.blocked is emitted with the error details.
  • Delivery exhaustion — The delivery orchestrator retries with exponential backoff. If all retries fail, a DeliveryExhaustedError triggers event.blocked.

Human-in-the-Loop (HITL)

Some agents need human input mid-conversation (e.g., approval, clarification). The pipeline supports this through two special events:

  1. The agent emits agent.input.requested describing what input it needs.
  2. The pipeline surfaces this to the user via the channel adapter.
  3. When the user responds, an agent.input.provided event captures their input.
  4. The pipeline resumes the agent with the provided input.
agent.invocation.requested
  └─▶ agent.input.requested   ← agent pauses, asks for input
        └─▶ agent.input.provided   ← user provides input
              └─▶ agent.response.completed   ← agent resumes and completes
