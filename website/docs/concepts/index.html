Architecture

How Chat Agent Relay connects chat platforms to AI agents through a canonical event model, pluggable adapters, and an append-only ledger.

High-Level Flow

Every message passes through the same pipeline, regardless of which chat platform sent it or which agent handles it:

Key Principles

  • Canonical events — Every platform message is normalized into a single event shape. Slack, Discord, WebChat, Telegram, Lark, and DingTalk all produce the same message.received event. Platform-specific data is preserved in provider_extensions.
  • Append-only ledger — Every event is appended to an immutable ledger. Events are never modified or deleted. This provides a complete audit trail and enables replay.
  • Pluggable adapters — Channel adapters and agent adapters are independent, swappable components. Add a new chat platform or agent runtime without changing the pipeline.
  • Interface-driven — Key boundaries (ChannelAdapter, AgentAdapter, ConfigStore, LedgerStore) are defined as TypeScript interfaces. Implementations are interchangeable.
  • Governance first — Policy evaluation happens before agent invocation. Messages can be blocked, filtered, or routed based on configurable rules.
  • Causal tracing — Every event carries correlation_id (links the entire request chain) and causation_id (links parent to child). This enables full traceability.
  • Structured logging — The server and channel/agent registries use structured logging rather than ad-hoc console output.

How a Message Flows

  1. Ingress — A chat platform sends a message. The channel adapter receives it and produces a canonical message.received event.
  2. Policy — The middleware evaluates governance rules. If denied, an event.blocked event is emitted and processing stops.
  3. Routing — The route engine selects an agent based on channel, pattern, or default rules. A route.decision.made event records the choice.
  4. Invocation — The selected agent adapter calls the agent runtime. An agent.invocation.requested event is recorded. For streaming agents, deltas arrive incrementally.
  5. Response — The agent returns a response. An agent.response.completed event captures the full reply.
  6. Delivery — The delivery orchestrator sends the response back through the channel adapter. A message.send.requested event is recorded, followed by message.sent on success.
  7. Ledger — Every event in this chain is appended to the ledger with causal links. The full conversation is queryable and auditable.
